### 1.2. Luồng hoạt động chi tiết (End-to-End Workflow)

```
[Chủ trì phòng họp (Host)]
          │
          ▼ Bấm nút "🔴 Bắt đầu ghi biên bản AI"
[Socket.IO Gateway] ──(Broadcast 'transcription:started')──► [Tất cả người tham gia trong phòng]
                                                                        │
┌───────────────────────────────────────────────────────────────────────┘
│  Mỗi người tham gia (Client):
│  - Nếu Micro ĐANG BẬT (isMicOn): Trình duyệt kích hoạt `webkitSpeechRecognition` (lang: 'vi-VN')
│  - Người nói phát biểu:
│      onresult (final) ──► Gắn { speakerId: user.id, speakerName: user.name, text, timestamp }
│      Bắn Socket: `meeting:transcript-chunk`
│  - Cơ chế Watchdog Auto-Restart: Nếu im lặng > 30s hoặc trình duyệt tự ngắt (`onend`),
│    tự động gọi lại `recognition.start()` nếu cuộc họp vẫn đang ghi.
└───────────────────────────────────┬───────────────────────────────────
                                    │
                                    ▼
                          [MeetingsGateway (NestJS)]
                         /                          \
                        /                            \
                       ▼                              ▼
          Broadcast 'meeting:live-caption'       Lưu chunk vào Database:
        (Tất cả mọi người thấy phụ đề thời     `MeetingMinute.rawTranscript`
         gian thực & cuộn Live Transcript)     (Append: [09:15:20] Tên: Lời nói)
                                                      │
┌─────────────────────────────────────────────────────┘
│  Khi Chủ trì bấm "Kết thúc cuộc họp" HOẶC "⏹️ Dừng & Tạo biên bản AI":
│  1. Socket.IO broadcast 'transcription:stopped' (Các máy dừng SpeechRecognition).
│  2. Backend gọi `MeetingAiService.generateFromTranscript(meetingId)`.
│  3. Gemini 1.5 Flash (1M tokens context) tiếp nhận toàn bộ transcript thô (50KB-100KB)
│     và trích xuất có cấu trúc:
│       - 📌 Summary: Tóm tắt 3-5 đoạn điều hành.
│       - 🎯 Decisions: Các quyết định đã thống nhất.
│       - 📋 Action Items: Danh sách việc + người phụ trách + deadline.
│       - ⚠️ Risks & Questions: Rủi ro & vướng mắc kỹ thuật.
│  4. Lưu vào `MeetingMinute` (các trường JSON) và broadcast 'minutes:ai-generated'.
└────────────────────────────────────────────────────────────────────────
```

## 2. THIẾT KẾ DỮ LIỆU & DATABASE SCHEMA

Tận dụng mô hình `MeetingMinute` sẵn có và bổ sung trường lưu trữ kịch bản hội thoại thô `rawTranscript`, đồng thời tạo bảng `MeetingTranscriptChunk` để truy vấn lịch sử hội thoại có cấu trúc:

### 2.1. Cập nhật Prisma Schema (`backend/prisma/schema.prisma`)

```prisma
model MeetingMinute {
  id                  String    @id @default(cuid())
  meetingId           String    @unique
  meeting             Meeting   @relation(fields: [meetingId], references: [id], onDelete: Cascade)
  content             String    @db.Text // Tóm tắt/nội dung biên bản chính (HTML/Markdown)
  rawTranscript       String?   @db.Text // Toàn bộ kịch bản hội thoại thô dạng [HH:mm:ss] Name: text

  // AI Summary fields (Gemini 1.5 Flash)
  aiSummary           String?   @db.Text
  actionItems         Json?     // [{ task, assignee, deadline, priority, confidence }]
  decisions           Json?     // ["Đồng ý dời deadline", "Chốt dùng Redis"]
  risksAndQuestions   Json?     // { risks: [], openQuestions: [] }
  aiGeneratedAt       DateTime?
  aiModel             String?   // "gemini-1.5-flash"
  aiTokensUsed        Int?
  isTranscribing      Boolean   @default(false) // Trạng thái đang ghi âm thời gian thực

  createdAt           DateTime  @default(now())
  updatedAt           DateTime  @updatedAt

  @@index([meetingId])
}

model MeetingTranscriptChunk {
  id          String   @id @default(cuid())
  meetingId   String
  meeting     Meeting  @relation(fields: [meetingId], references: [id], onDelete: Cascade)
  speakerId   String
  speakerName String
  speakerRole String?
  text        String   @db.Text
  timestamp   DateTime @default(now())

  @@index([meetingId, timestamp])
}
```

## 3. THIẾT KẾ BACKEND (NESTJS)

### 3.1. Socket.IO Signalling (`backend/src/meetings/meetings.gateway.ts`)

Bổ sung 4 socket handlers phục vụ Live Streaming:

1. **`meeting:start-transcription`**:
   - Chỉ Host / Creator / PM của cuộc họp mới có quyền kích hoạt.
   - Set `MeetingMinute.isTranscribing = true`.
   - Broadcast `meeting:transcription-status` `{ isTranscribing: true, startedBy: user.name }`.

2. **`meeting:stop-transcription`**:
   - Host bấm dừng ghi.
   - Set `MeetingMinute.isTranscribing = false`.
   - Broadcast `meeting:transcription-status` `{ isTranscribing: false }`.

3. **`meeting:transcript-chunk`**:
   - Nhận payload: `{ meetingId, text, isFinal }` từ client khi nói xong một câu.
   - Xác thực client thuộc phòng họp.
   - Broadcast `meeting:live-caption` `{ speakerId, speakerName, speakerRole, text, timestamp }` tới toàn phòng để render phụ đề trực tiếp.
   - Batch insert vào `MeetingTranscriptChunk` và append dòng `[HH:mm:ss] SpeakerName: Text\n` vào `MeetingMinute.rawTranscript`.

4. **`meeting:generate-ai-summary`**:
   - Kích hoạt phân tích toàn diện từ `rawTranscript` qua `MeetingAiService`.

### 3.2. Cập nhật `MeetingAiService` (`backend/src/meetings/meeting-ai.service.ts`)

- Nâng cấp method `generateSummary(meetingId: string)`:
  - Nguồn dữ liệu đầu vào: Ưu tiên `rawTranscript` (kịch bản cuộc họp thực tế từ giọng nói). Nếu chưa có transcript thì fallback sang `content` viết tay.
  - Xây dựng System Prompt tối ưu hóa cho biên bản hội thoại nhiều người (Multi-speaker meeting transcript):
    ```text
    Bạn là Thư ký Cuộc họp AI Chuyên nghiệp của hệ thống WorkSync.
    Dưới đây là toàn bộ kịch bản lời thoại trực tiếp (Live Transcript) của cuộc họp từ Web Speech API:
    ---
    ${rawTranscript}
    ---
    Hãy phân tích kịch bản trên và trích xuất JSON:
    1. summary: Tóm tắt nội dung cuộc họp mạch lạc, súc tích (3-5 đoạn tiếng Việt chuẩn mực).
    2. decisions: Danh sách các quyết định hoặc thỏa thuận then chốt đã chốt.
    3. actionItems: Danh sách việc cần làm (task, assignee là tên thành viên được giao, deadline nếu có nhắc, priority HIGH/MEDIUM/LOW).
    4. risksAndQuestions: Các rủi ro kỹ thuật hoặc câu hỏi thảo luận còn bỏ ngỏ.
    ```
- Xây dựng Heuristic Fallback khi không có API Key hoặc Gemini lỗi kết nối (đảm bảo 100% không crash hệ thống).

## 4. THIẾT KẾ FRONTEND (REACT + VITE + TAILWIND)

### 4.1. Speech Recognition Hook (`frontend/src/features/meetings/hooks/useLiveTranscription.ts`)

Hook quản lý toàn bộ vòng đời nhận diện giọng nói:
- Hỗ trợ `window.SpeechRecognition || window.webkitSpeechRecognition`.
- Thiết lập `recognition.continuous = true; recognition.interimResults = true; recognition.lang = 'vi-VN';`.
- **Cơ chế Watchdog Auto-Restart:**
  ```typescript
  recognition.onend = () => {
    if (isTranscribingActive && isMicOn) {
      // Tự động khởi động lại ngay khi im lặng ngắt
      try { recognition.start(); } catch (e) { /* ignore already started */ }
    }
  };
  ```
- Khi nhận diện `result.isFinal === true`:
  - Bắn sự kiện socket `meeting:transcript-chunk` với nội dung text đã chuẩn hóa.
- Khi người dùng **Tắt Micro (Mute)**: Tạm dừng recognition để bảo vệ quyền riêng tư. Khi **Bật Micro**: Tiếp tục lắng nghe.

### 4.2. Giao diện Phòng Họp (`frontend/src/features/meetings/components/VideoCallRoom.tsx`)

1. **Thanh điều khiển (Meeting Toolbar):**
   - Thêm nút: `🔴 Bắt đầu ghi AI` (Host only, khi bấm chuyển sang `⏹️ Dừng ghi`).
   - Huy hiệu `● Đang ghi biên bản AI` nhấp nháy êm dịu trên đầu màn hình cho tất cả người tham gia biết.

   - Tự biến mất sau 4 giây nếu không có ai nói thêm.
3. **Sidebar Drawer: Live Transcript & AI Summary (`MeetingAiDrawer.tsx`):**
   - **Tab 1: Kịch bản trực tiếp (Live Feed):** Hiển thị danh sách cuộn các câu thoại theo thời gian thực (ai nói, lúc mấy giờ, nội dung gì). Có ô tìm kiếm từ khóa trong cuộc họp.
   - **Tab 2: Biên bản AI (AI Intelligence):**
     - Nút `✨ Tạo lại biên bản AI` (Regenerate).
     - Thẻ **Tóm tắt điều hành (Executive Summary)**.
     - Thẻ **Quyết định đã chốt (Key Decisions)** với icon checkmark xanh.

     - Thẻ **Rủi ro & Câu hỏi tồn đọng (Risks & Questions)**.

## 6. TIÊU CHÍ NGHIỆM THU (DEFINITION OF DONE)

1. **Hiệu năng & Băng thông:** Cuộc họp 1–2 tiếng chạy êm ái, RAM trình duyệt tăng không quá 30MB, dữ liệu chữ truyền qua Socket.IO dưới 100KB.
2. **Khả năng tự phục hồi (Resilience):** Người dùng im lặng 1-2 phút rồi nói tiếp, hệ thống vẫn tự động nhận diện bình thường không bị đứt đoạn.
3. **Chính xác danh tính (Attribution):** Từng câu nói ghi đúng tên và ảnh của người đang bật micro phát biểu.
4. **Chất lượng AI Summary:** Gemini 1.5 Flash tóm tắt đầy đủ 4 phần (Tóm tắt, Quyết định, Việc cần làm, Rủi ro) trong vòng dưới 5 giây.
5. **Độ tương thích:** Hoạt động hoàn hảo trên Google Chrome, Microsoft Edge, Opera (có fallback cảnh báo nhẹ nhàng trên Firefox).
